# 分阶段实施及验收

每个实施阶段独立运行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`，记录结果与遗留事项。不以页面可见替代业务验收。

| 阶段 | 工作范围 | 验收方法 |
| --- | --- | --- |
| P0 设计 | 环境/兼容检查、目录、Schema、API、计划 | 文档逐项覆盖任务书；Prisma validate；明确边界与缺配置 |
| P1 基础（已完成） | 初始化、迁移/seed、真实PG、本地运行；首页、目录、详情、基础排行/合集/教程；登录与权限基础；Docker文件 | 空库迁移、幂等seed、唯一/外键/CHECK；HTTP health、搜索/筛选/排序/分页、404/400、数据库故障503；免费正文/会员拒绝；桌面移动视觉；四项质量门禁 |
| P2 GitHub采集（已完成） | 导入、发现、分页、去重、限速重试、增量快照、任务日志、后台仓库管理 | mock GitHub测试302/429/403/5xx、ETag304、断点恢复、重复导入；真实直连导入/刷新/两页发现已通过，详见phase-2-report；SSRF URL矩阵；日内只保留一条真实快照，增长展示等至少两个真实业务日 |
| P3 AI审核 | 可配置模型、JSON Schema、分类中文摘要、受众/难度/场景/评分、审核发布 | 未配置明确失败；注入README、无效JSON、未知分类、超时测试；真实模型1条实测；审批前前台不可见、拒绝不变、版本冲突409 |
| P4 编辑和会员 | 人工评测、专题教程CRUD、GitHub登录实测、收藏、会员授权、用户权限后台 | USER/EDITOR/ADMIN矩阵；收藏幂等及跨用户隔离；会员到期/撤销；HTML/RSC/API/预取均不泄露正文；未经实测无法标验证；关键流程浏览器完成 |
| P5 部署与验收 | Docker构建运行、TLS反代、备份恢复、运维任务、全部移动QA | 新宿主compose启动/迁移；PG健康检查；生产无demo；备份恢复校验；OAuth回调；限速并发；真实采集→AI→人工发布→会员教程完整回归 |

## P1 历史交付边界

P1没有实现生产采集worker、AI调用/审批、管理CRUD、会员开通/收藏完整流程、支付、近期增长或线上部署。P2新增采集worker和仓库管理，其余模块仍显示待建设或缺配置。P1快照初始化脚本不等价于P2采集器。

每个阶段分别保留交付报告：`docs/phase-1-report.md`、`docs/phase-2-report.md`，说明文件、实际门禁、数据库/HTTP/浏览器证据、环境限制与下一阶段。
